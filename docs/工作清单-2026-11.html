0. 结论先行

三条判断

  1. 已经饱和的是「生成」和「单点结构」：续写、扩写、润色、纠错、起名、单章章纲、结构化设定库，国内外都有人做，且平台内置工具免费。再做一遍不构成差异。
  2. 我们唯一别人没有的，是「可审计的组合闭环」：授权/自有作品 → 结构化拆解 → 可编辑 JSON 中间层 → 批量改编 → 体检/敏感词/相似度 → 带 AIGC 声明的 docx/md/txt + JSON 交付，再叠加 BYOK、多模型、本地/私有化与成本账本。单点都能被复制，组合很难。
  3. 可收费最小闭环还缺的不是功能，而是「能收钱、敢收钱、值这个钱」的三类基础设施：真实支付凭据与生产密钥、法律文本与权利确认、真实模型与质量基线。这三类不补，功能再多也只能卖人工服务。

最小闭环定义（验收用）

4 周摘要

  • 第 1 周：定价/法务口径拍板；支付凭据申请；生产密钥与 provider 收口；法律文本起草；数据清理。
  • 第 2 周：支付沙箱跑通；BYOK 透传；整本交付包；真实模型接入；黄金评测集与基线。
  • 第 3 周：付费墙/额度提示；弱网重试；一致性与相似度报告；退款/开票 SOP；3 家工作室试点。
  • 第 4 周：onboarding 与案例；通知/对账；收费试点；复盘与修复。

1.7 赛道结论

  1. 平台内置工具免费，但绑定生态。 阅文/番茄的 AI 是留存与创作辅助，不是可独立售卖的工程工具；离开平台，发布/签约/数据链路即失效。
  2. 中文独立工具已经会卖「拆书 + 生成 + 去 AI 味」。 但拆书多是一次性报告，中间层停在「大纲/人物标签/剧情树」，不是可复用、可 diff、可交付的资产。
  3. 海外工具把「结构化上下文」做成了标配。 Story Bible/Codex/Lorebook/Story Cards 证明用户愿意为「可编辑的设定层」付费；BYOK 是分水岭（Novelcrafter/KoboldAI/SillyTavern 开放，Sudowrite/NovelAI/AI Dungeon/Squibler 封闭）。
  4. 没有人同时做到完整闭环。 「拆解 → 可审计中间层 → 批量改编 → 体检/相似度 → 工程化交付 → BYOK/本地/私有化」目前没有对手同时具备；这是我们的空位，不是单点。
  5. 计费普遍是订阅 + credits/字数包，免费档在收窄。 Dreamily 停服、Sudowrite 收紧 credits，说明长尾免费工具正在出清；靠免费额度获客、靠订阅+用量包变现是可持续路径。

2. 结合已有材料的三个判断

2.1 判断一：已经饱和、我们不该做的能力

一句话：不要做「又一个能生成正文的写作器」，也不要把「拆书」当唯一卖点；这两件事都已经有人做，且平台免费。

2.2 判断二：唯一别人没有、且用户愿意付钱的能力

不是单点，是组合：

叠加差异：BYOK（本地完整，云端补透传）、多模型/任意 OpenAI 兼容端点、本地/离线、私有化部署、按本/章/字的成本核算。

谁愿意付钱：3–10 人工作室、代写/MCN、短剧改编方、机构/课程平台。个人作者愿意为「少返工」付小钱，工作室愿意为「可复用、可交付、可审计」付大钱。

为什么难复制：

  • 平台厂商（阅文/番茄）不会做「拆他人作品」，也不会开放 BYOK/私有化——这与它们的生态与版权立场冲突。
  • 海外工具（Sudowrite/Novelcrafter）不做中文网文工程化，也没有本地/私有化与中文敏感词/签约体检。
  • 中文独立工具（蛙蛙/笔灵/墨狐）没有 JSON 中间层、没有 BYOK、没有批量改编与工程化交付，且多为黑盒 SaaS。
  • 组合的每一环都需要数据契约、流程编排、合规留痕、交付格式同时到位，单点复制无法形成闭环。

必须避免的叙事：不能公开宣传「去抄袭/洗稿/换名改写」。对外统一说「合规拆解与再创作流水线」；默认 AIGC 标注、默认权利确认、默认相似度报告。能力可以强，叙事必须干净。
