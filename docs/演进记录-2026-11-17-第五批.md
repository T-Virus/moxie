# 在线版持续演进 · 第五批（2026-11-17）

本批承接第四批的「下一批候选」，落地五块：**退避抖动 + 下次重试时间可见**、**Sentry 采样/去重**、**SEO/PWA**、**大列表虚拟滚动**、**API 出参契约扩面**。所有改动仍在工作区未提交。

## 本批完成清单

### 1. 退避加 jitter + next_retry_at 暴露到详情 API

**现状**：第四批的指数退避是确定性值（base×2^(n-1)），同一时刻批量失败的上游任务会在同一秒重投，形成同频惊群；`next_retry_at` 只存库、前台看不到，运营无法判断「卡住」还是「等重试」。

**改动**：
- `tasks.py::retry_backoff_seconds` 加 **full jitter 变体**：先算 `delay = min(cap, base×2^(n-1))`，再在 `[delay/2, delay]` 均匀取值（`math.ceil` 保下限），同一次失败的不同任务落在不同时点。rng 可注入，测试确定性。
- 服务端 `task_to_dict()` 暴露 `next_retry_at`（ISO 或 null）；公开 `/v1/tasks/{id}` 与后台 `/v1/admin/tasks/{id}`（都用它）同时生效。
- 后台 `TaskBoard.vue` 详情新增「下次重试时间」：相对倒计时（N 秒后 / 已到点等待调度）+ 绝对时间；`admin/types.ts` 的 `TaskRow` 补字段。
- 单测：退避区间/封顶（jitter=0 下沿）、同失败抖动分散、`next_retry_at` 暴露、窗口内外验证共 6 个。

### 2. Sentry 转发采样率与去重

**现状**：第四批把前端错误全量转发 Sentry，只有端点级 IP 限流（30/min）；同一 JS 错误在多个用户侧爆发时仍会刷屏，打爆 Sentry 配额。

**改动**：
- 配置 `client_error_sentry_sample_rate`（默认 1.0 全量，0 关闭，0.x 抽样）、`client_error_sentry_dedupe_window_seconds`（默认 60s）。
- `services/sentry.py`：
  - `error_fingerprint()`：对 `source|code|path|脱敏 message` 取 SHA256，故意不含 request_id/ts，同一错误风暴归一到同一 key。
  - `_sample_by_fingerprint()`：按指纹哈希前 8 位做**稳定抽样**，同一错误恒定采中或不采中，避免抖动式采样。
  - `should_forward()`：采样 + 时间窗去重决策；进程内去重表带上限（2048）与 TTL 淘汰，防止指纹无限增长吃内存；未配 DSN 直接 False。
- `telemetry.py`：脱敏后先过 `should_forward` 再调 SDK；指标 `forwarded` 标签区分 `yes/no/error`（no=被采样或去重拦下）。日志链路不受影响，仍全量落结构化日志。
- 单测 4 个：窗口内去重、窗口过期可重发（注入 `now` 不 sleep）、采样率 0 关闭且不写缓存、50% 采样按指纹稳定分化；每用例清缓存隔离。

### 3. SEO / PWA

**现状**：`index.html` 只有 charset/viewport/theme-color/favicon，无 description/OG；无 manifest、无 service worker，无法安装到桌面、无离线壳。

**改动**：
- SEO：`index.html` 补 description / keywords / robots / OG(type,title,description,image) / twitter:card。
- PWA：`public/manifest.webmanifest`（standalone、start_url=/、双图标）、`public/icon.svg` + `icon-maskable.svg`、`public/sw.js`。
- **SW 安全边界**：只缓存 GET 同源；`/v1/` API 与带 query 的请求一律直通（加密 payload / 登录态 / 额度绝不落离线缓存）；导航 network-first、失败回退 index.html；`/assets/` 静态资源 cache-first（hash 文件名）；安装预缓存仅静态壳。
- `main.ts` 仅生产注册 SW（`import.meta.env.PROD`，避开开发 HMR 缓存陈旧），失败静默。
- 单测 6 个：SW 源码文本断言（只 GET / 排除 API / network-first / 壳无业务路由）+ manifest 结构 + index.html meta 引用。

### 4. 大列表虚拟滚动

**现状**：`BodyTab` 章节目录把全部章节（长篇可达 2000 章）一次性渲染，DOM 膨胀；其余列表（Runs 12 条/页、TaskCenter 分页、Items/Summaries 已 `paged`）已有分页。

**改动**：
- 新增纯逻辑 `utils/virtualList.ts::computeVirtualRange(count,rowHeight,scrollTop,viewportHeight,overscan)`：计算可见区间 + 上下占位高度，overscan 缓冲防白屏，overscroll 时钳制到尾部保证非空；`isIndexVisible()` 供视口判断。node 可单测。
- `BodyTab.vue` 目录改造：卷头 + 章行统一扁平为定高 34px 的 `TocRow[]`（折叠卷不产章行），只渲染 `visibleTocRows`，上下 spacer 撑出完整滚动高度；`@scroll.passive` 更新 scrollTop，`onMounted` 量容器高度。
- 章节切换的目录定位从 `querySelector('.is-active').scrollIntoView` 改为**按行索引算 scrollTop**（虚拟列表下目标行可能未渲染，DOM 查询失效）。
- 单测 6 个：空列表、顶部、中部高度守恒、底部钳制、短列表全渲染、可见判断。

### 5. API 出参契约扩面

**现状**：仅 `/v1/crypto/public-key` 有 `response_model`；稳定接口在 OpenAPI 里出参是隐式 any。

**改动**：
- `schemas.py` 新增 3 个出参模型（均继承 `_Base` 不套输入 trim）：`HealthResponse`（status/env/app）、`GenreItemResponse`、`GenresResponse`（items/custom_allowed/degraded 可选）。
- `/healthz` 与 `/v1/genres` 加 `response_model`；契约测试断言 `$ref` 指向组件、字段集合正确、运行时字段不被裁剪。
- 坑：`response_model` 会给可选字段补 `degraded=null`（不是缺失），前端 `Boolean(null)=false`、`|| ''` 均兼容，但 `client/types.ts` 的 `degraded` 类型同步改为 `string | null` 以如实反映契约。

## 坑与回归说明

- **jitter 下限**：`int()` 向下取整会跌破 `delay/2`（如 2.5→2），改用 `math.ceil` 保证下限语义，测试断言随之调整。
- **response_model 补 null**：可选字段会以 `null` 出现在运行时响应，不是缺失；全项目对 `degraded` 的消费均 falsy 安全，已核对。
- **虚拟滚动定位**：DOM 查询 `scrollIntoView` 在虚拟列表下失效（目标行未挂载），必须按行索引 `× 行高` 算 scrollTop。
- **admin TaskBoard 类型**：`formatRetryTime` 早期返回 `undefined` 与声明的 `string` 冲突，`detailMeta` 又传 `unknown`；改为返回空串 + `|| undefined` 交给既有 filter 过滤。
- **全量 pytest 必须串行**：并发跑会 fixture 级联 AssertionError（见第四批）。
