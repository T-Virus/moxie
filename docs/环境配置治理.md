# 环境配置治理（server / client / admin）

适用范围：仅 `/server`、`/client`、`/admin` 三个在线项目。离线桌面端不在本约定内。

## 1. 环境定义

| 环境 | 用途 | 数据来源 | 可关闭的门禁 |
| --- | --- | --- | --- |
| `dev` | 本机开发、E2E、联调 | 临时 SQLite / fakeredis / mock 支付 / stub 模型 | 可关邮箱验证、法务闸门、载荷加密强制 |
| `staging` | 预发布验收、回归、试点客户试用 | 独立 Postgres / Redis / 对象存储，真实支付沙箱 | 不得关闭生产 fail-fast；模型可 stub 但需标注 |
| `production` | 正式对外 | 生产 Postgres / Redis / 对象存储，真实支付与模型 | 不得关闭任何安全闸门 |

生产判定以 `ENV=prod|production|...` 白名单为准，不能写成 `staging` 绕过 `server/app/main.py` 的启动校验。

## 2. 配置分层

| 层 | 文件 / 来源 | 是否入库 | 说明 |
| --- | --- | --- | --- |
| 代码默认 | `server/app/config.py` | 是 | 仅开发占位；生产启动会拒绝弱口令与 `change-me` |
| 样例 | `server/.env.example`、`client/.env.example`、`admin/.env.example` | 是 | 只放占位符和说明，不放真实值 |
| 环境注入 | 部署平台的 Secrets / ConfigMap | 否 | 生产唯一可信来源 |
| 运行热改 | `runtime_config` 表 + admin「遥测配置」 | 否 | 仅采样率、去重窗口、灰度比例等低风险运营参数 |

前端侧：`client/.env` 与 `admin/.env` 不入库；仓库内只保留 `.env.example`。`VITE_API_PROXY` / `VITE_API_PROXY_TARGET` 在 dev 指向本地 server，生产走同源反代。

## 3. 敏感配置清单

必须在部署平台 Secrets 中管理，不可写入仓库、日志、CSV 或前端资产：

- `JWT_SECRET`
- `LICENSE_PRIVATE_KEY_PEM`
- `PAYLOAD_CRYPTO_PRIVATE_KEY_PEM`
- `ARTIFACT_SIGNING_SECRET`
- `MODEL_KEY_SECRET`
- `LLM_API_KEY`
- `WECHAT_*` / `ALIPAY_*` / `STRIPE_*` 私钥与回调密钥
- `S3_ACCESS_KEY` / `S3_SECRET_KEY`
- `SMTP_PASSWORD`
- `VAPID_PRIVATE_KEY`
- `METRICS_TOKEN`
- `MOCK_PAYMENT_SECRET`（dev/staging）
- `INVOICE_APP_SECRET`

生成方式：PEM 私钥用 `openssl`，随机串用密码学安全随机数；不要复用 JWT_SECRET 充当签名密钥。

## 4. 三环境基线差异

| 配置 | dev | staging | production |
| --- | --- | --- | --- |
| `DATABASE_URL` | 临时 SQLite | 独立 Postgres | 生产 Postgres |
| `REDIS_ENABLED` | false（fakeredis） | true | true |
| `PAYLOAD_ENCRYPTION_ENABLED` | 可 true / false | true | true |
| `PAYLOAD_ENCRYPTION_REQUIRED` | 可 false | true | true |
| `LICENSE_ALLOW_EPHEMERAL_KEY` | true | false | false |
| `PAYMENTS_MOCK_ENABLED` / `FAKE` | true | 仅沙箱 | false |
| `MODEL_STUB` | true | 可 true（标注） | false |
| `LEGAL_GATE_ENABLED` | 可 false | true | true |
| `EMAIL_VERIFICATION_REQUIRED` | 可 false | true | true |
| `TRUST_PROXY` | false | true | true |
| `METRICS_TOKEN` | 可空 | 必填 | 必填 |
| `SENTRY_DSN` / `CLIENT_ERROR_*` | 可空 | 必填 | 必填 |

## 5. 变更与回滚

1. 任何配置变更必须先改 `.env.example` 样例与本文档基线，再注入目标环境。
2. 生产变更走两步：先发布兼容新旧值的代码，再切换配置；禁止代码与配置同时跳变。
3. 密钥轮换：生成新值 → 双值过渡（如支持）→ 切换 → 观察 24h → 废弃旧值。
4. 数据库 URL、存储桶、签名密钥变更必须配套回滚脚本；回滚时优先恢复上一版配置，不先回滚代码。
5. 运行热改参数通过 admin 操作会写审计日志；每次发布复盘需核对近 7 天热改记录。

## 6. CI 校验

CI 只检查可静态验证的部分：

- `git diff` 不得包含 `.env`、密钥文件、私钥文件；
- `server/app/config.py` 生产闸门相关配置在测试中保持覆盖；
- workflow YAML、监控 YAML 可解析；
- 三端 typecheck/lint/test/build 不因配置样例漂移而失败。

真实环境注入值由部署平台权限控制，CI 不读取生产 secrets。
