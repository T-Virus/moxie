## 本批完成清单

### 1. 契约扩面（orders / usage / admin 列表）

前九批已覆盖 crypto / healthz / genres / plans / entitlements / audit / providers / notifications / push-subscriptions / subscriptions / tasks / agent-runs 固定路由，本批把订单、用量与后台核心列表纳入 response_model。

**用户侧 billing（3 路由）**：
- `GET /v1/orders/{id}` → `GetOrderResponse`、`GET /v1/orders` → `OrderListResponse`（顶层 key 是 `orders` 不是 `items`）、`GET /v1/usage` → `UsageListResponse`。
- 复用第九批的 `OrderView`（`meta: dict[str, Any]` 非 None）；新增 `UsageEventView`（`meta: dict[str, Any] | None`）——**关键**：`UsageEvent.meta` 直取 row.meta 可能为 None，schema 必须允许 None，否则 response_model 会把 None 裁掉/报错。测试专门种了一条 `meta=None` 的用量记录验证原样保留。

**后台 admin（6 列表）**：
- `GET /v1/admin/users` / `subscriptions` / `orders` / `tasks` / `alerts` 声明契约；`GET /v1/admin/notifications` 连同本批可视化字段一起契约化（见第 2 节）。
- 新 schema：`AdminAccountView`（内嵌 `AdminSubscriptionView`）/ `AdminSubscriptionsResponse` / `AdminOrderView`（`meta` 可 None）/ `AdminOrdersResponse` / `TaskBriefView`（Task+AgentRun 合并 17 字段）/ `AdminTasksResponse` / `AdminAlertView`（context 派生字段可 None）/ `AdminAlertsResponse`（额外 `window_hours` / `failed_notifications` / `webhook_failures` 全量声明）。
- 关键差异：`days_left` 后台是 int、用户侧是 float，分立两个 View；notifications 与 notification-deliveries 字段集不同（`subject/template` vs `category`），不共用 View。
- 刻意不动：`admin_task_detail`（`run_to_dict/task_to_dict` 动态）、`dashboard`、`get_user`、`admin_order_detail`、`webhook`、`model-configs`/`telemetry-config`（已有隐式返回类型注解契约）。

**前端**：admin `api.ts` 把 `users/subscriptions/orders/taskList/alerts/notifications` 从 `request<any>` 收敛为后端 raw 结构（snake_case），视图侧 `normalizeList<T>` 消费方式不变；client 端无 orders/usage 直接消费点，未新增无效类型。契约测试 16→18（订单+用量 1、后台列表 1），两端 typecheck 通过。

### 2. Web Push 投递回执可视化与 429 Retry-After 退避

**429 Retry-After 退避（后端）**：
- `services/webpush.py` 新增 `error_retry_after_seconds(exc, cap_seconds=3600, now=None)`：仅 status 429 时读 `WebPushException.retry_after`，支持纯秒数（`"120"`）与 HTTP-date（`email.utils.parsedate_to_datetime`），负数/非法串忽略，夹到 `[0, cap]`；非 429 / 无属性返回 None。
- `config.py` 新增 `notification_push_retry_after_cap_seconds = 3600`（env `NOTIFICATION_PUSH_RETRY_AFTER_CAP_SECONDS`），防畸形 header 卡死投递数天。
- push 分支逐订阅捕获 429：解析建议值写入 `receipt.retry_after_seconds`，多订阅取最大值放 `delivery.meta["retry_after_seconds"]`（避免过早重投仍被限流）；429 不清退订阅。
- 新增 `_retry_delay(delivery, settings, fallback)`：`emit`（首次固定 300s）与 `retry_deliveries`（线性 300×n）两处统一为「meta hint 优先，否则兜底」。5xx / 无 header 仍走原固定退避，既有语义不变。

**投递回执可视化（admin）**：
- 后端 `GET /v1/admin/notifications` 增字段：`max_attempts` / `next_retry_at` / `provider_message_id` + `meta_summary`（`subscribers/delivered/expired_count/receipt_count/retry_after_seconds/reason`）——列表只放摘要，不返回完整 receipts（避免 200 行 × N 设备撑爆响应）。
- 新增 `GET /v1/admin/notifications/{id}` 详情路由（support 可读）：返回完整 `meta`（`receipts` 逐订阅 `sub_id/status/http_status/error/retry_after_seconds`、`expired` 列表）。新 schema 声明 `meta: dict[str, Any]` 不裁剪。
- `admin` 前端：`NotificationRow` 补回执/重试字段与 `NotificationDetail` 类型；`Alerts.vue` 通知表格新增「送达」`delivered/subscribers`（含失效数）与「下次重试」倒计时列，操作列加「详情」按钮 → `Modal.vue` 弹层展示投递标量 + 逐订阅回执表 + 失效原因；新增 `.detail-grid` / `.detail-section` 样式。
- 通知测试 16→26（Retry-After 参数化 5 + HTTP-date + 仅 429 + 429 驱动退避 + 5xx 兜底 + 详情路由），全过。

### 3. 去重参数后台可配

第九批已把 `sample_rate` / `dedupe_window_seconds` 接入 `OperationalSetting` + `runtime_config`（DB 持久化 + 60s 缓存）+ admin `TelemetryConfig` 页；**唯一未接入的是 `dedupe_max_entries`**（第九批还是硬编码常量），本批补齐全链路：

- `config.py` 新增 `client_error_sentry_dedupe_max_entries = 64`（env 默认，与 `sentry._DEDUPE_MAX_ENTRIES` 对齐）。
- `runtime_config.py`：`telemetry_defaults` 补 `dedupe_max_entries`（clamp 1..1024）、`_sanitize` 补 int 校验（排除 bool）、`set_telemetry_config` 补入参；**旧 DB 行缺该字段时由 defaults 自动补齐，无需迁移**。
- `schemas.py`：`TelemetryConfigView` 补 `dedupe_max_entries: int`、`TelemetryConfigUpdate` 补 `Field(ge=1, le=1024)`（pydantic 与服务层范围一致，避免「放过但回退默认值」的隐晦行为）。
- `admin.py` PUT 传参 + 审计 meta 补字段；**`telemetry.py` 调用 `should_forward` 补 `dedupe_max_entries=cfg[...]`——这是让后台值真正生效的关键**（否则存了不用）。
- 前端 `TelemetryConfig.vue` 加第三个输入框（容量上限 1..1024）+ 类型/api 同步；`.env.example` 补 3 个 Sentry 默认值 + 推送 Retry-After cap。
- 测试：`test_runtime_config.py` 全量调用点补 `dedupe_max_entries`，新增旧行兼容 + 60s TTL 过期（此前是空白：用 `now` 注入 t0 / t0+59 / t0+61 验证缓存命中与过期）；`test_telemetry.py` 新增端点透传测试（patch `should_forward` 断言 kwargs 含后台值）。运行时配置 6→8、遥测 22→23，全过。
