# 在线版持续演进 · 第十五批（2026-11-18）

> 主题：实时性、输入规范、运维自闭环与消费对账。四项需求均在现有 server/client/admin 体系内合并实现，不引入新的前端框架或独立后台。

## 1. 用 SSE 代替前端接口轮询

### 后端
- 新增 `server/app/services/sse.py`：统一 SSE 帧编码、载荷加密 AAD 路径与响应头，避免各端点重复实现 `x-payload-sse`。
- `agent_runs.py` 新增 `GET /v1/agent-runs/stream`（注册在 `/{run_id}` 动态路由之前，避免被详情接口吞掉）：
  - 按 `account_id` 聚合同一账号的 queued/running/paused 运行签名；
  - 状态变化时只发 `event: refresh`，前端收到后重查列表，不为每个 run 开连接；
  - 单条过程日志仍走既有 `/{run_id}/events`，职责不混。
- `admin.py` 新增：
  - `GET /v1/admin/tasks/stream`：聚合 Task + AgentRun 活跃签名，运营看板列表/概览变更推送；
  - `GET /v1/admin/tasks/{task_id}/events`：任务详情增量事件流，`since` 续传，`event: status` 推状态，`data:` 帧推日志；`require_staff`，不复用用户端本人 run 流。

### 前端
- `client/src/services/agentApi.ts` 抽出统一 SSE 解析器，新增 `streamRunFeed()`；`client/src/composables/useRunFeed.ts` 实现「SSE 优先 + 404/405/501 降级轮询 + 断流重连 + 无活跃任务自动断开」。
- `Runs.vue`、`TaskCenter.vue` 移除 6s / 4s 列表轮询，改接账号级 SSE；`document.hidden` / `busyId` 守卫保留。
- `admin/src/payloadCrypto.ts` 补 `decryptSse()`；`admin/src/api.ts` 新增 `streamTasksFeed()` / `streamTaskEvents()`。
- `TaskBoard.vue` 详情日志 4s 轮询与列表 10s 轮询改为 SSE；保留每秒本地时钟用于相对时间显示；SSE 不支持时自动降级。

## 2. 前端输入 trim

- `client/src/services/http.ts`、`admin/src/api.ts`：请求体在加密前统一递归 trim；短文本/标识/备注自动去首尾空白。
- 白名单在原有口令、令牌、密钥、`content` 基础上补 `body`、`prompt`：通知正文与提示词保留原始空白；服务端 `schemas.py#_NO_TRIM_KEYS` 同步，避免前后端口径漂移。
- 新增 `http.test.ts` / `api.test.ts` 覆盖普通字段 trim 与白名单保留。

## 3. /admin 数据库备份、邮件通知与恢复

- 配置：`config.py` 新增 `BACKUP_ENABLED / BACKUP_SCHEDULE_ENABLED / BACKUP_INTERVAL_MINUTES / BACKUP_DIR / BACKUP_RETENTION_COUNT / BACKUP_EMAIL_ENABLED / BACKUP_NOTIFY_EMAILS`；`.env.example` 同步。
- 服务：`services/backup.py`
  - SQLite 用 `Connection.backup()` 在线快照 + `PRAGMA integrity_check`；PostgreSQL 用 `pg_dump -Fc`，缺客户端返回 501；
  - manifest 落 `sha256`、大小、触发方式、引擎，**不落明文 DATABASE_URL**；
  - 备份完成后按收件人列表发 SMTP 邮件，发送失败不阻断备份，状态写回 manifest；
  - `BACKUP_EMAIL_TRANSPORT=fake` 复用既有通知环境变量做本地模拟；
  - 保留数量由 `BACKUP_RETENTION_COUNT` 控制。
- 调度：`scheduler.py#run_once()` 追加 `db_backup` phase，按间隔判定，最近已有备份则跳过。
- API（全部 `response_model`）：`GET/POST /v1/admin/backups`、`GET /backups/{id}/download`（ZIP）、`POST /backups/{id}/restore`、`DELETE /backups/{id}`；读 `require_staff`，写/下载/恢复 `require_admin`，全部写审计。
- 恢复边界：默认 `mode=staged`，只生成校验副本与 `RESTORE_GUIDE.md`；`apply=true` 必须带 `confirm=RESTORE`，覆盖当前库前 `db.dispose()`，SQLite 清理 stale `-wal/-shm`，Postgres 走 `pg_restore --clean --if-exists`。UI 用 Modal + 输入确认，不用裸 `window.confirm` 作为唯一闸门。
- 前端：`Backups.vue`（列表、手动备份、下载、暂存/覆盖恢复、删除、邮件状态）+ roles/router/api/types/权限测试接线。
- 测试：`test_backup.py` 覆盖生命周期、权限、暂存取、恢复确认闸门、定时间隔跳过。

## 4. AI 模型消费统计后台

- 数据口径：统一从 `usage_events(metric='model_token')` 聚合；`meta` 新增 `provider` 字段写入点覆盖 agent 编排、网关同步/流式、拆书与改编 runner。
- `services/model_gateway.py#provider_of()` 从模型名与网关域名推导供应商；历史数据缺 provider 归 `unknown`，不影响 token/成本汇总。
- `services/usage_stats.py` 纯 Python 聚合，规避 SQLite/Postgres JSON 方言差异；支持 `days/group_by(provider|model|account|day)/provider/model/route/account_id` 筛选；返回 token、成本（分）、计费事件数、账户数、模型数。
- API：`GET /v1/admin/usage/models`（`response_model=ModelUsageResponse`，`require_staff`）。
- 前端：`ModelUsage.vue` 汇总卡 + 成本占比条 + 明细表，支持维度切换与筛选，无需跨平台翻日志对账。
- 测试：`test_usage_stats.py` 覆盖聚合、筛选与 support 只读权限。

## 设计取舍与后续

- 聚合流是「服务端按 0.2s 检查签名 + 推送 refresh」，不是前端每几秒打列表接口；避免 N+1 SSE 连接，且不支持 SSE 的部署自动回落原轮询。
- 备份只覆盖数据库；S3/MinIO 与本地产物卷仍由既有 ops 脚本单独同步，避免把备份与产物混在一个不可移植包里。
- 消费成本目前沿用全局 `model_price_cents_per_1k_tokens`，统计结果适合对账总量；按模型差异化定价是后续独立需求。
- 下批候选：备份恢复演练自动化（drill 结果可视化）、备份加密与异地复制、按模型差异化成本价、Web Push 批量回执 CSV 导出、灰度命中档位日志。
