## 1. P0 · 阻断对外运营（4 项）

### P0-1 `nginx/` 目录不存在，线上网关起不来

- **证据**：`docker-compose.web.yml` 声明 4 个只读 bind mount：`../nginx/default.conf`、`../nginx/certs`、`../client/dist`、`../admin/dist`。实测 `D:\Code\moxie\nginx` **路径不存在**。
- **后果**：`docker compose -f docker-compose.yml -f docker-compose.web.yml up` 时，Docker 会为缺失的源路径创建空目录，nginx 容器拿到的是**空 conf 目录** → 无站点配置 → 要么起不来，要么返回默认 404。而这是文档里写的"线上唯一入口"（HTTPS、`/admin` 路径分发全在这里）。
- **动作**：把 `default.conf` / `default.https.conf` 纳入仓库（若被 `.gitignore` 排除，需改为 `*.example.conf` 入库 + 部署时拷贝），并把 overlay 纳入 CI 冒烟。

### P0-2 真实支付零验证（三条 live 测试无条件 skip）

- **证据**：`server/tests/test_payments.py:441 / 448 / 455`——即使配置了 `STRIPE_SECRET_KEY` / 微信商户凭据 / 支付宝沙箱凭据，仍执行 `pytest.skip(...)`。代码注释即"已配置 key 时请手动运行沙箱下单冒烟"。
- **后果**：微信 v3 回调验签、支付宝异步通知、退款、部分退款、对账——全部只在 mock 签名下验证过。真实渠道的字段差异（金额单位、单号格式、证书序列号、`out_trade_no` 长度限制）没有任何回归保障。
- **动作**：改造成"有凭据即真跑"的 `-m live` 用例，或加一个 `scripts/payment_smoke.py` 手动脚本并在 `docs/` 留一次真实沙箱下单+回调+退款的证据（订单号、回调原文、退款单号）。这是"能不能收钱"的物理前提。

### P0-3 生产身份从未在真实编排里跑过

- **证据**：当前运行的 compose 栈 `/healthz` 返回 `"env":"dev"`。
- **后果**：`main.py` 的生产强校验（强密钥、禁 mock、禁默认 DB、License 私钥必填）、`docs_enabled` 关闭、S3 凭据必填——这些分支在真实编排里**一次都没被触发**。上线当天 `ENV=production` 第一次生效，很可能直接启动失败，且没人知道会挂在哪个校验点。同时 dev 模式下 `/docs`、`/openapi.json` 对外暴露，属信息面风险。
- **动作**：造一份 `.env.production`（一次性随机密钥、真实 PG/MinIO 凭据），在 CI 或本机把整套 compose 以 production 启动一次，断言：`/readyz` 200、`/docs` 404、`/openapi.json` 404、`/metrics` 不被公网暴露。

### P0-4 编排与网关没有 CI 门禁

- **证据**：`.github/workflows/ci.yml` 8 个 job 中无 compose 相关 job；`docs/engineering.md` 自述"本机无 Docker"。
- **后果**：目前"生产形态能起来"只靠人工执行过（当前正在跑的那套）。任何 `docker-compose.yml`、Dockerfile、overlay、`.env.example` 改动都没有回归保护——而它们恰恰是最容易一改就全线崩的文件，且失败只在部署时暴露。
- **动作**：新增 `compose-smoke` job：`docker compose config` → `up -d --build` → 轮询 `/readyz` → overlay 版再跑一次 nginx `wget 127.0.0.1` 健康检查 → `down -v`。

## 3. P2 · 工程债与演进决策（6 项）

### P2-1 双实现并行，维护面翻倍

`src/webapp.py`（**207KB** 单体）+ `web/`（旧前端）+ `server/`&`client/`（新一套）——同一产品存在两套后端、两套前端。`engineering.md` 明确"后续仅覆盖 server/client/admin，离线端按存量保留不再新增能力"，但实测 `src/` 最后改动是 **2026-11-18**，仍在演进。
**动作**：要么真冻结（加 CI 规则：`src/`、`web/` 变更需 PR 显式豁免），要么定一个下线日期。中间状态最贵。

### P2-2 没有 CD、没有灰度、没有回滚

`release.yml` 只产出 GitHub Release + SBOM + cosign 签名 + provenance，**不含部署步骤**；上线仍靠 ssh + 手工 compose。`docker-compose.web.yml` 也没有蓝绿/滚动策略。
当前规模可接受，但必须写清"回滚 5 分钟操作手册"（数据库迁移不可逆时尤其关键——18 个迁移里没有一个写 downgrade 演练记录）。

### P2-3 备案清单缺失

`docs/法务与SLA交付包-2026-11.md` 中"备案"仅出现 1 次。对外运营前需要：ICP 备案、公安机关联网备案、**生成式人工智能服务备案 / 算法备案**（《生成式人工智能服务管理暂行办法》要求），以及 AIGC 标识办法要求的显式+隐式标识落地检查。协议文档齐全，但"能不能合法对外运营"的前置清单没有。

### P2-4 i18n 已明确跳过，与出海目标冲突

`engineering.md` 范围约定写明"i18n 与站点地图继续跳过"。这与 BP 里"海外市场 69.83 亿元"的扩展叙事直接冲突。作为决策可以接受，但需在 BP 里同步删掉出海红利，避免两套口径。

### P2-5 压测没有回归基线

`ops/loadtest/RESULTS.md` 只有 2026-11-04 一次本机数据（10 VU / 30s / 888 请求 / p95 45–160ms），未纳入 CI，也没有随版本变化的趋势。当前对"改成这样会不会慢一倍"没有任何自动回答能力。

### P2-6 C 端缺少搜索、帮助中心与新手引导

client 无 `Help/Guide/Onboard/Faq` 组件，无站内搜索（`search|搜索` 命中 0）。14 个页面全靠顶栏导航；BP 自己把"首日流失"列为风险 8，但对应的承接物（引导、示例、帮助）都还没做。

## 4. 建议明确"不做"的四项

避免继续横向扩张，导致上面的缺口长期不闭合：

1. **i18n / 出海**（已声明跳过，保持一致）
2. **SaaS 多租户**（当前是单租户 + 多账号，改造代价远大于收益）
3. **插件市场**（`skills_catalog.json` 已够用，外部插件会引入审核与安全成本）
4. **Mac / iOS 客户端**（双实现债未清前不应增加第三套壳）

## 5. 建议的执行顺序

**第一批（收钱前必须做，约 2–3 人日）**
1. P0-1 补 `nginx/default.conf` + `default.https.conf` 入库
2. P0-3 用 `.env.production` 把整套 compose 以 production 身份跑通一次
3. P0-4 把 compose smoke 加进 CI
4. P0-2 真实支付沙箱冒烟并留证据

理由：这四项全部指向同一件事——**"能不能安全地把钱收进来"**。任一项缺失，上线首日就是事故日。

**第二批（首个付费用户前，约 3–5 人日）**
5. P1-6 统一运行时为 3.12（本地 venv 重建 + `.python-version`）
6. P1-5 `/readyz` 增加 S3 / 模型网关探活
7. P1-4 补 alertmanager 与一条真实告警通道（飞书/企微 webhook 即可）
8. P1-7 给 admin 的关键写操作补行为测试（当前 40 页面 / 5 测试文件最不成比例）

**第三批（对外文案与代码对齐，约 1 人日）**
9. P1-1 短剧导出：**要么补最小导出（分集大纲 + 剧集 JSON），要么从定价页与 BP 撤掉**
10. P1-2 移动端：明确标记"仅离线版"，或补云端登录

**第四批（结构性决策）**
11. P2-1 双实现的冻结或下线日期（最贵的一笔债）
12. P2-3 备案清单落地

## 6. 一句话结论

**工程完成度远高于 11-04 那份清单所描述的水平——测试全绿、18 个迁移、生产校验、支付治理、CI 八道门禁都是真的。真正卡住的不是"代码写得不够多"，而是三个"从未被真实执行过"：真实支付、production 身份的编排、线上网关。这三个都只会在上线那天第一次运行，而它们恰好是唯一无法靠补功能绕过去的东西。**
