# 在线版持续演进 · 第十一批（2026-11-17）

本批按用户要求"结合网文创作 10 环节 Skill，完善补全现有项目技能体系，确保数据一致性、修改同步"推进。
与前几批不同，本批**不改后端业务接口与前端**，而是补体系层的唯一事实源、自动校验与文档纠偏。
所有改动仍在工作区未提交。

## 背景摸底（决定方案的关键事实）

- 项目有两套并存技能体系：桌面 `config/studio.json#bindings` + `src/studio.py#BIND_STAGES`（11 工序），
  云端 `server/app/agents/registry.py#build_registry()`（13 技能）+ `graph.py` 三图。二者不互通。
- 10 环节里桌面覆盖 8 项完整、2 项部分；云端唯一功能性空洞是**正文生成链断裂**
  （`chapter_expand`/`chapter_write` 只剩孤儿 `.pyc`，`engine.py` 仍引用其 state key）。
- 文档严重超前于代码：两份 DAG 文档声称已落盘的 `config/flow.json`、`src/flow.py`、
  `scripts/flowctl.py`、`tests/test_flow.py` **实际均不存在**；`docs/项目缺口清单-2026-11.md`
  声称 `src/updater.py` 已实现且已接线，实际文件不存在、`webapp.py` 无相应调用。
- WorkBuddy 的 `script-writing-studio` 是短剧/AI 视频分镜工具，与网文 10 环节只是同名不同物，不纳入本体系。

## 本批完成清单

### 1. 建立 10 环节技能体系唯一事实源

新增 `config/skills_catalog.json`（schema_version 1.0）。每条环节声明：
`id / index / name / external（外部 Skill 名）/ trigger（4 个触发词）/ purpose / coverage /
desktop{stages,files,api,note} / cloud{skills,files,api,note} / ssot（数据写权）/ writes / next / gap / reference`。

- `coverage` 三态：`full` / `partial` / `cloud_gap`，杜绝"看起来都有、实际不知道哪断了"。
- `trigger` 共 40 个，全局唯一；`next` 下游引用可机器校验（本批写入时发现并修正了 1 处误写引用）。
- 所有 `files` 用仓库相对路径，写盘前逐一核对存在性；不存在的 `web/OutlineTab.vue` 未写入。
- 把"网页端只看文档、云端只看 registry"的割裂收敛到一份可校验清单。

### 2. 新增一致性校验脚本 + 补配置缺口

新增 `scripts/check_skills.py`（纯标准库，AST 解析，无需 `server/.venv`）：

- `--check`：10 环节数量/id/index/触发词唯一性、`coverage` 枚举、`next` 引用、所有引用文件存在、
  `studio.json#bindings` 覆盖 `BIND_STAGES`、清单声明的桌面工序已绑定、云端技能都在 `SkillRegistry` 注册。
  AST 解析 `src/studio.py#BIND_STAGES` 与 `registry.py#build_registry()` + 各技能类 `name`，避免导入重依赖。
- `--drift`：扫描 `docs/*.md` 中含"已落盘/实际落盘/已实现/已落地/实际契约/真实可执行"等强声明
  且无否定词的行，提取反引号路径并报告磁盘上不存在的文件。软报告，不阻断提交。
- 无参数 = 两者都跑；硬校验失败 exit 1。

补齐 `config/studio.json#bindings.cover = p_mvw8s21n`：此前 `BIND_STAGES` 有 `cover` 工序但绑定表缺失，
是脚本抓出的第一处真实漂移，现已对齐（11/11）。
