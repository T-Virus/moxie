# 在线版持续演进 · 第十二批（2026-11-17）

本批按用户明确要求推进：**把 10 个创作技能"合并优化"进 server / client / admin 三端产品**，
而不是把外部 Skill 当作独立插件引入执行。核心是把技能作为产品一等公民——
一份 SSOT 清单、后端统一合并暴露、用户端可发现、管理端可治理，三端数据改一处同步。

## 用户诉求与方案决议

用户原话："按照提供的 skills 同 /server /client /admin 项目进行补全完善技能项，不是单一的引入执行，是合并优化"。

- ❌ 不做的：把 oh-story-claudecode / humanizer 等外部仓库装成 WorkBuddy 独立 Skill 来调用；
  那些只是能力参考，不是本项目运行时。
- ✅ 要做的：把 10 环节能力织进现有产品三端，共用第十一批建立的 `config/skills_catalog.json`，
  以"技能目录"形式让用户在前端看到、让运营在后台核对、让后端统一供数。

## 本批完成清单

### 1. 后端：统一技能目录 API（合并层）

- `config.py` 新增 `skills_catalog_path`（留空自动探测部署布局，支持环境变量 `MOXIE_SKILLS_CATALOG` 覆盖）。
- 新增 `services/skill_directory.py`：
  - 读 SSOT `config/skills_catalog.json`，按 **mtime 增量缓存**（改清单下次请求即生效，无需重启）；
  - 合并 `SkillRegistry.catalog()` 的实际注册名，给每项标 `available/registered`——
    让"清单声明"与"代码实际"可对照，这是合并优化的核心；
  - 用户端 `_user_item` 只出产品语义字段（id/index/name/external/trigger/purpose/coverage/available/entry），
    管理端 `_admin_item` 额外出 gap/ssot/writes/next/双端 note与files/registered/reference；
  - **降级不阻断**：清单缺失或损坏返回 `degraded` + 空 items，不抛 500（与 genres 同策略）；
    显式路径失效会回退自动探测，全失效才降级。
- 新增 `api/skills.py`：`GET /v1/skills`（登录可读）、`GET /v1/admin/skills`（require_staff 只读），
  均已声明 `response_model` 契约；`main.py` 注册两条路由。
- `schemas.py` 新增 `SkillEntryView`/`SkillItemView`/`SkillsCatalogResponse`/
  `AdminSkillItemView`/`AdminSkillsCatalogResponse`；管理端 View 继承用户端 View 再补治理字段，避免两套字段漂移。

### 2. 用户端：技能目录页（可发现）

- 新增 `services/agentApi.ts#fetchSkills()`；`types.ts` 加 `SkillItem`/`SkillsCatalog`/`SkillCoverage` 契约类型。
- 新增 `views/Skills.vue`：10 环节卡片列表，展示覆盖状态徽标（完整可用/部分可用/云端完善中）、
  能力说明、触发词标签、入口 API；降级态与加载/错误态齐全；页脚显示目录版本与更新时间。
- `router.ts` 加 `/skills`（requiresAuth），`App.vue` 登录态导航加「技能」入口。

### 3. 管理端：技能治理页（可审计）

- `api.ts#skills()` + `types.ts` 契约类型；`roles.ts` 新增 `skills:read` 权限（admin/support 均只读开放）。
- `router.ts` 加 `/skills` 路由 + 导航「技能目录」（运维监控分组）。
- 新增 `views/Skills.vue`：汇总卡（技能项/三态计数/云端已注册数）+ 数据表格（技能项/覆盖状态/云端注册/入口工序）
  + 详情弹层（能力说明/缺口/SSOT 写权/触发词/注册技能与工序/落盘字段/文件引用/参考来源）。
  复用 `PageHeader`/`StatusBadge`/`Modal`/`StateBlock` 既有组件，风格与其他运维页一致。

### 4. 一致性与测试

- 扩展 `scripts/check_skills.py`：新增"三端接线"硬校验——后端双路由+注册、用户端 API/页面/路由/导航、
  管理端 API/页面/路由/权限共 11 处，任一端没接上即失败。这是"修改同步"机制的落地。
- 新增 `server/tests/test_skills.py`（11 条）：SSOT 读取、用户/管理视图字段边界、降级（全路径失效）、
  mtime 变更热重载、显式路径失效回退、API 鉴权（匿名 401/普通用户管理端 403/admin 可读）、
  OpenAPI 契约、API 环节集合 == 磁盘 SSOT。
- `server/tests/test_skills_catalog.py`（第十一批 10 条）保留并纳入回归。
- `admin/src/roles.test.ts` 补 `skills:read` 断言与导航可见性断言。
- `server/.env.example` 补 `SKILLS_CATALOG_PATH` 注释，配置文档与代码同步。

## 附带说明

- 三端"数据一致性"由 `config/skills_catalog.json` 单点保证：后端读它、前端只消费 API、校验脚本盯住接线，
  不存在前端硬编码的环节清单。改环节定义 → 改 SSOT → `check_skills.py` 验证三端未掉线。
- 管理端 `skills:read` 对 support 也开放（只读），与 `telemetry:read`/`presets:read` 的既有惯例一致。
- 后端 API 均登录/鉴权后才可读，技能目录不暴露给匿名访客（客户端路由同样 requiresAuth）。
- 用户此前明确不做 i18n / 站点地图，本批未涉及。
