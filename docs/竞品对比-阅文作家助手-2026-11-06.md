# 竞品对比：阅文/起点官方写作工具 vs 墨写工作台

> 对比对象：作家助手（App / 桌面端 / 网页）、妙笔、妙笔通鉴（问全书 / 知识库）  
> 对比范围：AI 功能清单、作者实际价值与限制、与我方「拆解→改编→章节写作→体检」工作台的逐项差距、差异化定位  
> 查询日期：**2026-11-06**（Asia/Shanghai）｜公开页面会变动，签约/采购前请复核  
> 阅读约定：`【官方】`=阅文官方页面/协议/版本说明；`【媒体】`=P1 媒体报道；`【作者社区】`=签约作者或用户发言；`【我方·代码】`=本仓库源码/文档；`【未证实】`/`【假设】`=不作为事实使用

---

## 0. 结论先行

**一句话：阅文官方工具是「码字 + 发布 + 签约」的操作系统，AI 是嵌在写作页里的辅助问答/润色/章纲；墨写是「拆解→改编→体检→成稿」的工业化中间层。两者不是替代关系，正面对打必输，互补定位才有机会。**

三个判断：

1. **功能面**：阅文在「起名/简介、灵感、润色、纠错、章纲、发布、签约、作品数据」上明显更强；在「参考作品结构化拆解、可编辑中间层、批量改编、体检报告、BYOK、多模型、本地/离线、工程化导出」上**明确不做**（或只做很浅）。
2. **商业面**：阅文是「免费 + 官方分发 + 墨水消耗」；我方是「订阅 + 用量 + 席位 + 私有化」。**不要跟免费打，要跟「可交付、可审计、可私有化」打**。
3. **风险面**：阅文官方明确禁止 AI 洗稿；「参考他人作品→换名→逐章改编」不能作为公开卖点。我方能力可以做，但叙事必须转成「合规再创作 / 改编差异报告」，否则增长越快、法律与平台风险越大。

**三条可执行定位（详见 §6.3）**：

- **投稿前工作台**：不替代作家助手码字，做「开书前拆解 + 投稿前体检」的互补工具。
- **工作室交付台**：批量拆解/改编/体检 + 可编辑 JSON 中间层 + docx/md/txt + 成本账单 + 私有化。
- **合规再创作**：权利声明 + 差异报告 + 敏感词/风险体检 + AIGC 披露；明确「不洗稿、不绕过检测、不保证签约」。

## 2. 阅文官方 AI 功能清单（逐项）

| 7 | **敏感词 / 风险提示** | **仅部分** | 发布「风险段落提示」「预审」[S3]；写作页「会员风险提示」[S8]；智能纠错 [S3] | 偏**发布前审核提示**；是否有独立全文敏感词库扫描，官方未明确 →【未证实】；第三方称可识别「敏感表述」[S19]，仅参考 |

## 4. 与我方能力的逐项对比

> 我方现状以仓库代码/文档为准：`src/decompose.py`、`src/adapt.py`、`src/expand.py`、`src/review.py`、`src/sentinel.py`、`src/compliance.py`、`src/export_book.py`、`src/usage.py`、`server/`、`docs/墨写商业计划书-2026-11.md`、`docs/项目缺口清单-2026-11.md`。[S21][S22][S23][S24]  
> 「谁更强」分两层：**能力面**（能不能做）与**成熟度**（是否开箱即用/稳定/有分发）。避免把「有代码」说成「比官方强」。

### 4.1 写作辅助层

| 能力 | 阅文（作家助手/妙笔） | 墨写（我方） | 谁更强 | 关键差距 / 机会 |
|---|---|---|---|---|
| AI 起名/简介 | **有**：妙笔指令生成书名+简介 [S4] | **有**：模型可生成书名/简介（`adapt.py` 书级命名、`decompose.py` 梗概） | **阅文**（入口即时、免费） | 我方不做独立起名器；可把它做成「拆解后自动命名 + 多版本对比」的附属能力 |
| 灵感/设定灵感 | **有**：设定灵感、灵感便签、模板中心 [S3][S8] | **仅部分**：`story_bible` 字段 + 提示词，无专门灵感 UI | **阅文** | 不正面做「灵感社区」；做「从参考书提炼灵感/桥段」 |
| 正文续写 | **无**（官方未见）；仅「后续十章章纲」[S4] | **有**：`expand.py` 章节正文扩写；`adapt.py --sequel-chapters` 续集 | **墨写**（能力面） | 这是我方少数「阅文明确不做」的正文级能力；但不要宣传「一键成书」 |
| 改写/润色/纠错 | **有**：润色、深化剧情、提升代入感、纠错 [S4]；智能纠错 [S3] | **仅部分**：`adapt.py` 改编级改写；`review.py` 只诊断不改写 | **阅文**（逐句体验） | 不跟它比「润色手感」；我方做「改编级重写 + 体检建议」 |
| 大纲/章纲 | **仅部分**：章纲提取、后续十章章纲、模板 [S2][S4][S8] | **有**：拆解产出全书设定 + 逐章任务；`adapt.py` 章数规划；`storymap.py` | **阅文**（单章提取） / **墨写**（全书结构） | 我方强在「全书结构 + 可编辑」；弱在「随手一问」的轻体验 |
| 人物/势力设定 | **有（辅助）**：角色关系、设定灵感、模板、角色管理 [S2][S4][S8] | **有**：21 个全书要素、24 个角色卡字段、10 类势力、18 种关系、9 种立场（[S21] §1.1；`story_bible.py`） | **墨写**（结构化） | 我方是字段化/可编辑/可导出；阅文是对话式/模板式 |
| 敏感词/风险 | **仅部分**：发布前风险段落提示/预审 [S3] | **有**：`sentinel.py` 本地词表扫描，命中词/次数/级别/上下文/下标；词表可自定义 | **墨写**（可审计、可离线） | 我方强在「全文扫描 + 可复现」；弱在「平台审核规则库」不如官方实时 |
| 章节体检/签约评估 | **无 AI 签约评估**；仅发布风险提示 [S3][S9] | **有**：`review.py` 多维体检（AI 味、主题偏离、错别字、设定/剧情一致性、违规风险、逻辑连贯、行文统计）+ 模型复核；带原文引用/行号/修改清单 | **墨写**（系统化） | 我方不承诺「签约评分」；输出「高危/中危 + 怎么改」，不自动改写、不承诺绕过检测 |
| 数据榜/热词 | **有（部分）**：作品数据、读者画像、作家指数榜 [S3][S8] | **无**平台数据接入；仅本地 `usage`/`Stats.vue` | **阅文** | 不做平台数据；可做「拆解报告里的结构指标」而非平台榜单 |
| 发布/签约链路 | **有**：一键发布、定时、预审、申请签约 [S3][S9] | **无**平台发布 API；导出后人工投稿（`export_book.py`） | **阅文** | 不碰发布/签约；做「投稿前最后一公里」的体检与格式整理 |

### 4.2 结构化/工程层（我方主战场）

| 能力 | 阅文 | 墨写 | 谁更强 | 关键差距 / 机会 |
|---|---|---|---|---|
| 参考作品结构化拆解 | **无**：只做自己稿件章纲提取 [S8] | **有**：`decompose.py` 支持 reference/outline 两种模式；输出 `decomposed.json` + `chapters.json`；12 万字符分段、10–16 章/段、8192→32768 重试、`--local` 无模型模式（[S21] §1.1） | **墨写（独有）** | 核心差异；但要绑定「自有/授权/公版」权利声明（`compliance.py`） |
| 结构化改编/换名改写 | **无**：官方禁止 AI 洗稿；改编仅限阅文 IP [S4][S10] | **有**：`adapt.py` 默认 1:1 章号映射；`--target-chapters` 扩写/压缩；`--sequel-chapters` 续集；名字映射；4 路并发；20 章/段 → 约 15 章/批（[S21] §1.1） | **墨写（独有，但高风险）** | 能力是差异，**叙事是生死线**：不能叫「去抄袭」；要输出差异报告、人工改写、AIGC 披露 |
| 可审计中间层 | **无**：黑盒对话 | **有**：`decomposed.json` / `chapters.json` 可逐章编辑；`compliance.jsonl` 权利声明留痕；`usage.jsonl` 调用记录；云端有审计日志 [S23][S24] | **墨写（独有）** | 工作室愿意为「可检查、可复用、可交付」付费；这是订阅的支点 |
| BYOK / 自带 Key | **无**：只能用官方模型 [S3] | **有（本地）**：Key 从本机 localStorage/环境变量读取；云端服务端支持 `X-BYOK-Key`，客户端尚未接线（[S22] P1-3） | **墨写（独有）** | 本地 BYOK 是完整卖点；云端 BYOK 要补客户端透传，否则套餐承诺落空 |
| 多模型 | **仅部分**：官方内置 DeepSeek V4.1 + Qwen3-Max [S3] | **有（配置级）**：OpenAI 兼容端点，`llm_base_url` / `llm_model` 可配；默认 DeepSeek | **墨写**（任意端点） / **阅文**（开箱双模型） | 我方强在「可换供应商/可私有化」；弱在「没有内置模型选择 UI」 |
| 本地/离线 | **仅部分**：本地保存/离线码字，AI 需联网 [S13] | **有**：Windows exe、`127.0.0.1` 本地 Web、`--local` 无模型模式；数据在 `data/<书名>/`（[S23]） | **墨写**（本地优先） | 对保密工作室/机构是硬差异；但 Mac/Linux/iOS 缺（[S22] P2-9） |
| 导出工程化 | **仅部分**：章节/草稿导出；Word 为第三方口径 [S14][S20] | **有**：`export_book.py` 合成 docx/md/txt；云端产物预签名下载；70+ HTTP 接口；JSON 中间层 | **墨写** | 不做「平台一键发布」；做「可投稿文件 + 可复用数据 + API」 |
| 成本计量/额度 | **仅部分**：墨水消耗，无 token 明细 [S5][S6] | **有**：`usage.py` 记录 token/耗时/成本；服务端 `usage_events`/`usage_aggregates`/`entitlements` 额度账本 [S23][S24] | **墨写** | 工作室可按本/按章核算毛利；这是「比免费工具更贵但更可控」的理由 |
| 批量/工作室 | **无**：个人码字工具 | **有（部分）**：多书目录、改编 4 路并发、云端任务/worker；但多人协作/版本树弱（[S22]） | **墨写**（批量） | 先做「批量 + 交付」，不要先做「多人协作」；后者成本高、需求验证不足 |
| 账号/订阅/支付/发票 | **仅部分**：免费+会员/墨水 [S10] | **有**：服务端账号/设备/License/订阅/额度/订单/退款/发票/管理后台（[S24]） | **墨写**（SaaS 底座） | 基础设施已建；但运营/支付上线仍需真实渠道与合规（[S22]） |
| 多端 | **有**：Android/iOS/鸿蒙/桌面/网页 [S1][S3] | **仅部分**：Windows exe + Android APK；无 iOS/Mac/Linux | **阅文** | 不在移动端正面竞争；先做 Windows 工作室 + Web 云端 |
| 品牌/分发/信任 | **有**：官方、免费、3.7 万评分、4.8 分、免费榜 #132 [S1][S3] | **无**：新品牌，无分发 | **阅文** | 不投品牌广告；用案例、报告、成本账单、开源/插件建立信任 |

**一句话总结对比**：

> **阅文赢在「入口、免费、全端、发布/签约闭环」；墨写赢在「结构化中间层、可迁移改编、体检报告、本地/BYOK/多模型、成本透明、工程化导出」。**  
> 前者是「作者每天打开的工具」，后者是「工作室/编辑每本书交付的流水线」。两者的使用频次和付费理由不同，不应该按同一维度比「谁功能多」。

## 5. 「有起点大神站台」的真实含义

### 5.1 证据拆解：官方背书、作者口碑，还是营销合作？

| 说法/现象 | 证据 | 性质 | 可信度 |
|---|---|---|---|
| 「全网顶流作家首选网文创作工具」 | 阅文官网、App Store 描述 [S1][S3] | **官方营销口号** | 官方确实这么写；但「首选」无公开数据支撑 → 营销口径 |
| 「作家之声」署名作者评价 | 下载官网列出林悦南兮、青衫取醉、薄也、呜喵王之怒等 [S13] | **作者口碑/用户评价** | 真实署名，但属于产品页精选评价，不是正式代言 |
| 「编辑指路 + 大神攻略」 | 5.0 活动页 [S7] | **社区内容运营** | 官方活动确实存在；「大神」是内容栏目，不是产品背书 |
| 「平台作家一览：唐家三少、孑与2」 | 作家专区「成为作家」页 [S12] | **平台作者名单** | 他们是阅文平台作者，不是作家助手代言人 |
| 「爱潜水的乌贼创作课」 | 作家专区推荐课程 [S12] | **课程讲师** | 平台作者/讲师合作，不是产品代言 |
| 「拼字闯关：起点大神等你闯关」 | 桌面端 V1.16.0 版本说明 [S8] | **游戏化营销** | 用「大神」做玩法包装，不是功能背书 |
| 「正式代言/签约站台」 | 未找到官方代言公告/合同 | **未证实** | 不能当事实；只能判断为「官方营销 + 作者口碑 + 社区内容」组合 |

**结论**：  
「有起点大神站台」更准确的说法是：**阅文用官方身份、平台作者名单、社区「大神攻略」和精选作者评价，构成一种「官方背书感」；但没有证据表明存在正式的付费代言或签约站台。** 它既不是纯粹的作者口碑，也不是严格意义的官方功能背书，而是**营销叙事 + 社区运营 + 平台作者资源**的混合体。

### 5.2 对获客与信任的影响有多大？

| 维度 | 影响 | 判断 |
|---|---|---|
| **获客** | 官方 + 免费 + 全端 + 应用商店排名（免费效率榜 #132、3.7 万评分）是主因；「大神」是降低首访戒心的催化剂 | **强，但不是决定性**；用户最终因为「免费/好用/能发布」留下 |
| **信任** | 官方身份让用户默认「不会跑路、数据在平台、能签约」；但 AI 功能差评会反噬品牌 | **中等偏强**；品牌不保证 AI 满意度 |
| **转化** | 「大神都在用」对新人有效；对成熟作者/工作室，作用有限，他们更看交付与保密 | **分层有效**：新人 > 成熟作者 > 工作室 |
| **对我方** | 不能借「大神」名义；也不需要在「大神」叙事上竞争 | **不跟**；用可验证的作者案例、体检报告、成本账单建立信任 |

**作者社区的真实反馈**（说明品牌不能替代产品）：

- 「问全书的话，我才 12 万字就已经开始胡言乱语了…10 章 10 章的问，有一些伏笔铺垫他又联系不上」[S5]
- 「手机端完全用不了」「只有 PC 端能用」[S5]
- 「不怎么样，错漏百出」「感觉差评一片」[S5]
- 「浪费我 300 墨水，不如不用」[S5]

这些反馈来自官方社区公开评论，**不代表全部用户**，但足以说明：**「大神站台」能带来首访，不能保证留存；AI 长文可靠性仍是行业共同难题。**

## 6. 结论：避开哪些正面战场、主打哪些差异点

### 6.1 应当避开的正面战场

| 不打的战场 | 原因 | 我方策略 |
|---|---|---|
| **通用码字/编辑器** | 阅文免费、全端、稳定、有云同步/历史版本；我方重做一个编辑器没有胜算 | 不做编辑器；做「导入/导出 + 外部写作」 |
| **AI 续写/润色/纠错/起名（单点）** | 阅文在写作页内即用、免费、体验成熟；单点工具会被「免费」碾碎 | 不卖「一键润色」；卖「改编级重写 + 体检建议」 |
| **发布/签约/平台数据** | 阅文是平台方，链路闭环；外部工具无法复制 | 不碰发布；做「投稿前体检 + 格式整理」 |
| **移动端/全端体验** | 阅文 Android/iOS/鸿蒙/桌面/网页全覆盖；我方只有 Windows+Android | 先做 Windows 工作室 + Web 云端；移动端只做「查看/审批」 |
| **品牌广告/「大神」叙事** | 阅文官方品牌+平台作者资源；我方新品牌无预算 | 不投品牌广告；用案例、报告、社区口碑 |
| **「AI 率降到 0 / 包过检测」** | 平台规则与法律风险极高；阅文官方也禁止洗稿 | 明确不做；只做「风险提示 + 人工改写」 |

### 6.2 应当主打的差异点

1. **结构化拆解 + 可编辑中间层**：把参考书变成 `decomposed.json` / `chapters.json`，章节、角色、势力、伏笔、道具都可检查、可改、可复用。阅文只做「自己稿件的章纲提取」，不做这个。
2. **可迁移改编 + 批量交付**：源章→目标章映射、名字映射、扩写/压缩/续集、4 路并发；一本参考书可产出多个版本。阅文明确禁止洗稿，也不做批量改编。
3. **体检 + 合规报告**：`review.py` 多维体检 + `sentinel.py` 敏感词扫描 + `compliance.py` 权利声明；输出高危/中危、原文引用、修改清单。阅文只有发布前风险提示，没有系统化体检报告。
4. **本地 / BYOK / 多模型 / 私有化**：数据不出机、Key 自己掌控、任意 OpenAI 兼容端点、Windows exe/本地 Web。阅文只能用官方模型、AI 必须联网。
5. **成本透明 + 工程化导出**：token/耗时/成本可查；docx/md/txt + JSON + 70+ HTTP 接口 + 云端预签名产物。阅文只有章节导出，没有成本账本/API。
6. **工作室交付台**：多书、批量、任务队列、额度账本、管理后台；按席位/项目收费。阅文是个人工具，不做工作室席位/审稿流。

### 6.3 三条可执行的差异化定位建议

#### 建议 1：做「投稿前工作台」，不做「第二个作家助手」

- **话术**：「作家助手负责写，墨写负责开书前拆解、投稿前体检。」
- **入口产品**：免费「2 万字拆解 + 体检报告」——上传 2 万字，输出 1 页结构报告 + 高危/中危清单；需登录看完整版。
- **为什么可行**：阅文不做参考书拆解、不做系统体检；作者在「开书前/投稿前」有真实痛点，且不与日常码字冲突。
- **KPI**：报告→注册 ≥30%，注册→付费 ≥8%；体检报告分享率。
- **边界**：不承诺签约/过稿；报告只做「风险提示 + 修改方向」。

#### 建议 2：做「工作室交付台」，按「批量 + 保密 + 可交付」收费

- **目标客户**：3–10 人网文工作室/代写团队，每月 3 本以上。
- **产品组合**：批量拆解/改编/体检 + 可编辑 JSON 中间层 + docx/md/txt 导出 + 成本账单 + 私有化部署。
- **价格锚**：¥199/月起（BYOK），¥299/月（托管）；¥1,999/季试点；企业 ¥19,800/年起（参考 [S21] §5）。
- **为什么可行**：阅文不做批量/席位/私有化；工作室愿意为「可复现交付 + 数据保密」付费。
- **KPI**：3 家试点、2 家续费；单本交付周期缩短 ≥30%；毛利率 ≥70%。

#### 建议 3：做「合规再创作」，把「可审计」变成信任卖点

- **产品能力**：权利声明（自有/授权/公版）→ `compliance.jsonl` 留痕；改编差异报告（人物/情节/主线变化比例）；`sentinel.py` 敏感词/风险扫描；AIGC 披露建议。
- **话术**：「不洗稿、不绕过检测、不保证签约；每一步可审计、每一版可回溯。」
- **为什么可行**：阅文官方明确禁止 AI 洗稿 [S4]；平台对 AI 正文容忍度低（作者社区称起点「不建议使用任何 AI」[S18]，【未证实官方规则】）；「合规」是工作室/机构采购的硬门槛。
- **边界**：不做「去抄袭」宣传；不做「AI 率降到 0」；不做批量起号。把「参考他人作品」默认改为「自有/授权/公版」，并提供「结构迁移」而非「逐章换名」。

## 7. 风险与边界（必须写进产品与营销）

| 风险 | 事实/证据 | 后果 | 我方必须做什么 |
|---|---|---|---|
| **改编权/实质性相似** | 参考作品→换名→逐章改编，法律上更接近「改编」而非原创；商业计划书引用宁波 25 万、厦门 15 万判例 [S21] §4.2 | 单案赔偿、下架、企业客户不敢采购 | 默认「结构迁移」而非逐章映射；权利声明；差异报告；相似度/人工复核；法务审合同 |
| **平台 AI 规则** | 起点 AI 占比 >10% 触发处理（商业计划书引公开报道 [S21]）；作者社区称起点「不建议使用任何 AI」[S18]【未证实官方】 | 作品被移出榜单/拒签/封号 | 不做「绕过检测」；输出 AIGC 披露建议；强制人工改写；限制批量 |

| **长文一致性** | 我方跨批依赖 `name_map`/`target` 映射，缺语义一致性检查（[S21] §4.1 风险 3） | 人物动机漂移、伏笔断、章节重复 | 建黄金评测集；人名/关系/时间线/伏笔自动检查；章节级重生成 |
