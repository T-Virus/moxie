- `vapid_private_key` / `vapid_public_key` / `vapid_subject`：与前端 `VITE_VAPID_PUBLIC_KEY` 成对，私钥只走服务端环境变量、不进契约、不进后台配置。

**发送服务**（新 `services/webpush.py`）：
- 包一层 pywebpush，暴露可注入的 `send_push(subscription, payload, settings)`；私钥未配置时返回 skipped，不抛错。
- 依赖：`pywebpush>=2.2,<3`（装了 2.5.0，传递依赖 `http-ece` / `vapid` / `http-vapid`），同步进 `requirements.txt` 与 `requirements.lock.txt`、`Dockerfile` 构建链。

**通知服务接入**（`services/notifications.py`）：

- `emit()` 默认渠道在 `inapp`/`email` 之外加 `push`（有订阅才实际发）；`retry_failed()` 同样透传 session 给 push 分支。
- 新增订阅管理函数：`upsert_subscription` / `remove_subscription` / `list_subscriptions`，endpoint 幂等 upsert。

**API**（`api/notifications.py`）：

- `schemas.py`：`AdminNotificationRequest.channels` 的 Literal 增加 `push`；新增 `WebPushSubscriptionView` / `WebPushSubscriptionResponse` 及订阅入参 schema。

**前端闭环**（`client`）：
- 新 `services/pushApi.ts`：`toPayload()`（subscription.toJSON → 三元组 + device_label，可单测）、`reportSubscription()` / `unreportSubscription()`，走统一 `apiFetch`，把 `push.ts` 保持为纯能力探测/订阅工具，node 测试不被网络层污染。

### 2. 去重缓存从 Redis 单键升级为滑动窗口

**现状**：第七批用 `SET NX EX` 固定窗口，窗口边界两侧几乎同时到达的两个错误会各放行一次（边界瞬时双发）。

**改动**（`services/sentry.py` + `tests/test_telemetry.py`）：
- `_dedupe_in_redis()` 改为 Redis zset 滑动窗口：key 前缀换 `moxie:sentry:dedupe:sw:`，成员/score 都是放行时的 epoch 秒。
- 用 `WATCH` + `MULTI` 乐观事务保证原子：watch key → `ZREMRANGEBYSCORE` 清窗口外 → `ZCARD` 判空 → 空则 `ZADD` 占位 + `EXPIRE` 兜底 TTL → `EXEC`；`WatchError` 重试至多 5 次，彻底消除读空与占位之间的竞态。
- 时间基准分开：Redis 路径用 wall-clock `time.time()`（多 worker 时钟需同一基准），本地回退缓存仍用 `time.monotonic()`（进程内单调时钟更稳）。
- Redis 异常仍回退进程内缓存，语义不变。
- 关键决策：fakeredis 未装 lupa、不支持 Lua `eval`，故不用脚本而用 `WATCH`/`MULTI`（fakeredis 与真实 redis-py 均支持），保证单测与生产走同一套原子路径。
- 测试改写为 zset 断言：共享实例同指纹只放行一次、清 key 后可重发、Redis 故障回退；新增滑动窗口语义测试（窗口内的重复被拦、旧时间戳滑出后可重发）。

### 3. 虚拟滚动推广到 admin AuditLogs / Alerts

**现状**：两个列表都是服务端分页（审计 50/页、告警与通知 30/页），服务端 `page_size` 上限 200；单页全渲染在 200 行量级有卡顿。

**改动**：
- 新可复用组合式 `admin/src/utils/useVirtualRows.ts`（含 6 单测）：定高行 + 上下 padding + overscan，暴露 `range` / `visibleRows` / `onScroll` / `resetScroll`；底层复用 `computeVirtualRange`。
- `AuditLogs.vue`：pageSize 提到服务端上限 200，表格放进固定高度滚动容器（`.vtable`），只渲染可见切片，切页/查询时 `resetScroll`；保留 Pager 做跨页导航。
- `Alerts.vue`：告警表与通知表同样虚拟化（告警行含账号副行，用 `.vtable-row--tall` 48px 定高区分），pageSize 提到 200，切页/筛选重置滚动。
- `style.css`：加 `.vtable` 定高行 / spacer 规则；复制正文仍取原始行数据，不受 DOM 切片影响。
