## 1. 一句话规则

> DAG 只是依赖声明，不是执行脚本。**上游输入一律从「上一次冻结的磁盘快照」读**，所以任何一个节点 / Skill 都能脱离整条流水线单独跑；跑完默认按依赖表向下传播，`--no-propagate` 才只看本地效果。

最小调度粒度是 **Skill**。Skill 内部再细分的 `subtasks` 是字段组/产出清单，不是调度单元——否则 41 个 Skill 会拆成 150+ 次调用，成本翻倍。

## 4. 按 Agent 细分的 Skill 契约

### `trend_discover` · 全网本月霸榜作品发现 Agent（5 个 Skill）

#### `trend_discover.source_fetch` · 公开榜单采集

- **单跑**：`python scripts/dagctl.py plan --book <book> --target trend_discover.source_fetch`　可单跑：是　幂等：是
- **读取**：config/trend_schema.json#sources（来源白名单与 URL 参数）；公开榜单页与作品详情页元数据
- **写出字段**：rankings[].rank_raw；rankings[].title；rankings[].author；rankings[].genre；rankings[].word_count；rankings[].metric_raw；rankings[].source_url；rankings[].captured_at
- **内部细分（subtasks）**：1) 本月榜单口径与来源白名单校验；2) 按 channel/type/cat_id 采集男女频阅读榜；3) 采集起点阅读指数榜等名次源；4) 字体反爬解码与 decode_failed 剔除；5) 按 title+author 去重
- **产物**：`data/<book>/dag/trend_discover.json#skills.source_fetch`　**入口键**：`dag.skill.trend_discover.source_fetch`
- **调用**：`no_llm`（不调 LLM）　**缺输入**：`fail`　**退出态**：`frozen`
- **传播**：book_select(review)
- **前置校验**：必填字段齐全、枚举合法、跨节点引用走稳定 ID
- **约束**：只读榜单页/详情页元数据，绝不抓正文、章节、试读或付费内容；不依赖原本书

#### `trend_discover.dimension_tag` · 三轴分类归一

- **单跑**：`python scripts/dagctl.py plan --book <book> --target trend_discover.dimension_tag`　可单跑：是　幂等：是

- **写出字段**：rankings[].channel；rankings[].length_class；rankings[].serial_status；rankings[].inferred_fields
- **内部细分（subtasks）**：1) 男频/女频：URL 参数与女生榜优先，题材兜底；2) 长篇/短篇：平台标签优先，字数阈值兜底（≤10 万字为短篇）；3) 已完结/连载中：完本/完结/连载等原值归一；4) 推断项标 inferred=true，取不到写 null
- **产物**：`data/<book>/dag/trend_discover.json#skills.dimension_tag`　**入口键**：`dag.skill.trend_discover.dimension_tag`

## 5. 单跑统一执行契约

| 项 | 规则 |
|---|---|
| 总原则 | DAG 只声明依赖，不决定执行顺序。任何节点、任何 Skill 都可以脱离整条流水线单独执行；上游输入一律从「上一次冻结的磁盘快照」读取，而不是要求本次上游跑过。 |
| 快照写入 | 每个 Skill 只替换 data/<book>/dag/<agent>.json#skills.<skill_id> 这一块；同 Agent 其余 Skill 的版本号、产物、指纹保持不动。 |
| owner 边界 | 单跑同样受 owner 唯一原则约束：只能写自己的 owner_fields；发现别人字段有错只能提交 conflict/patch 建议。 |
| 传播 | 单跑默认触发传播（一致性同步即由此实现）；--no-propagate 用于只改一处、先看效果的场景，此时产物标记 stale_downstream，下次 deliver 前强制复检。 |
| 并发 | 同书同节点互斥（复用 webapp.py JOB_LOCK）；不同节点并行时读取同一 lineage 快照版本，版本漂移则拒绝合入。 |
| 幂等 | 同一 target + 同一输入指纹重复执行直接返回缓存；重跑不产生新版本，除非 output_hash 变化。 |
| 失败策略 | fail → 立即中止不写盘；use_last_frozen → 用上版产物继续；empty_ok → 建空索引；user_gate → 等人工确认；blocking → 阻断整条 DAG。 |

### 四种入口

- `skill`：`python scripts/dagctl.py plan --book <book> --target <agent>.<skill_id> [--no-propagate] [--apply]`
- `node`：`python scripts/dagctl.py plan --book <book> --target <node_id> [--skills a,b] [--no-propagate]`
- `review_only`：`python scripts/dagctl.py plan --book <book> --target consistency`
- `full`：`python scripts/dagctl.py plan --book <book> --target full`

### 每个 Skill 单跑都走的 6 步

- 1 resolve_target：解析 node / skill，查 can_run_alone 与所属 owner
- 2 load_snapshot：按 reads 读取冻结产物 + lineage 版本校验，缺输入按 on_missing 降级
- 3 precheck：必填/枚举/ID 引用校验；指纹未变直接返回缓存（零调用）
- 4 execute：按 call_mode 组装 prompt 并执行；只写自己的 writes 字段块
- 5 change_set：对本 Skill 产物做字段级 diff，记录 old/new/author/ts
- 6 propagate：查 dependency_map 标记 dirty 节点 → 拓扑序并行 patch/rebuild → consistency 复检 → deliver 冻结

## 6. 典型单跑时序

**A. 只改世界观，不动别的**

```
target=outline.worldview → 读 meta.json + 原著分段 + craft.decompose_guide（冻结快照）
→ 只替换 dag/outline.json#skills.worldview → change_set
→ 传播 geography(patch) / factions(patch) / graph(rebuild)
→ consistency 复检 → deliver 冻结；book_meta / power_system / plot_spine / selling 四个 Skill 版本不动
```

**B. 只重跑一个 Skill 做预览**

```
target=outline.power_system --no-propagate
→ 只产 power_system 的新值，不写关联；产物标记 stale_downstream，下次交付前强制复检
```

**C. 一致性审查单独跑**

```
target=consistency（review_only）→ rule_check(无 LLM) → cross_check(claim 比对)
→ arbitrate → patch_write（只产 patch 交 owner）→ recheck → 输出 qa_score 与未决清单
```

**D. 只重新导出大纲**

```
target=deliver.outline_doc → 从冻结快照读全部字段 → 按 7 模块组稿
→ 写 output/<book>-大纲.md/docx，不重生成任何内容
```

**E. 一键改大纲的联动**

```
用户提交 change_set → owner=outline 锁定该路径
→ 查 dependency_map 第 2 条 → dirty = items/characters/volumes(patch) + graph(rebuild)
→ 四个节点并行重跑（输入只有原产物 + 变更 + 被点名字段）
→ consistency 比对「等级表 ↔ 道具品阶 ↔ 第44/223/315章战斗力」
→ 仲裁回写 → 复检收敛 → deliver 冻结，展示影响 4 个模块 / 3 处章节
```

全程不跑 trend_discover / geography / factions，也不重拆全书。

## 7. 验收断言（由 scripts/dagctl.py validate 校验）

1. 11/11 节点 standalone.enabled = true，且每个节点有独立 CLI 入口
2. 41/41 Skill can_run_alone = true，fqid 全局唯一，均可被 --target 直接命中
3. 每个 Skill 的 reads / writes / subtasks 三项均非空，writes 字段引用 docs/outline_fields.json 命名
4. 每个 Skill 的 writes 不越出所属 Agent 的 owner_fields；派生节点显式声明只读上游
5. 所有 propagates_to 指向已注册节点，mode ∈ {patch, rebuild, review}
6. 单跑输入只依赖冻结快照，不要求本次上游执行；缺输入按 on_missing 明确降级
7. 单跑默认触发依赖传播，--no-propagate 只做本地预览并标记 stale_downstream
8. 指纹命中可跳过、重复执行幂等、同书同节点互斥
9. consistency 单跑只产 patch / 结论，不直接改其他节点数据
10. deliver 单跑可在不改内容的前提下重新导出大纲与投稿包
