## 本批完成清单

### 1. 可观测性：requestId 全链路 + 前端错误上报

后端原本已有完整的 requestId 基础设施（生成/透传/响应头/结构化日志/错误体/CORS expose），
但前端只解析、不上报——浏览器端异常与服务端日志是断开的。本批把这条链路补上。

- **新端点** `POST /v1/telemetry/client-error`（匿名）：
  - 新增 `api/telemetry.py`，接收错误摘要并写结构化日志（`moxie.client_error`）。
  - 双 requestId 关联：`request_id` 是上报请求自身的（中间件注入 contextvar），
    `source_request_id` 是"出错的那次请求"的 id（前端从错误响应体取），两者并存可跨端关联。
  - 输入不可信：`schemas.ClientErrorReport` 全字段限长 + `redact()` 正则脱敏
    （token/api_key/Bearer/JWT/password/signature）+ URL 去掉 query（防 token 随日志外泄）。
  - 独立限流 `client_error_rate_limit_per_minute=30`，防错误风暴挤占业务配额/日志洪泛；
    计数指标 `moxie_client_error_reports_total{result,source}`。
  - payload 加密豁免（加密会话失效时正是最需要上报的场景，避免"错误无法上报"死循环），
    前端两处 `payloadEncryptionApplies` / `encryptionApplies` 也同步豁免。
- **前端全局捕获**（client + admin 各一份 `errorReporter.ts`）：
  - `window.error` + `unhandledrejection` 全局钩子，`main.ts` 安装。
  - 只上报网络错误 / 超时 / 5xx；4xx 属用户侧问题不上报。
  - 裸 fetch（`keepalive`，不走 apiFetch）——杜绝上报自身被加密/401 刷新/再次上报的递归。
  - 30s 同错误节流（避免刷屏）、`lastRequestId` 由每次响应头回填，供无上下文的 JS 异常关联。
  - 上报失败静默，绝不影响用户主流程。
- client 单测 +6（errorReporter：4xx 过滤/5xx 携带 id/网络错误/失败吞掉/节流/id 关联），
  后端单测 +6（脱敏/URL 清洗/匿名上报/字段校验/限流）。

### 2. 任务可靠性：失败有限重试 + 死信

现状盘点：Task 已有 `attempts` 字段、租约超时重排（sweep_leases）、卡住重排、手动 requeue；
AgentRun 已有节点级/段级重试和 paused 续跑。**唯一缺口**是任务执行失败后立即落 `failed`，
瞬时错误（上游抖动/限流）被过早判死。

- `services/tasks.py` 的 `execute_task` 失败分支加入有限重试：
  - 新增配置 `task_max_attempts=3`（`config.py`）。
  - `attempts < 上限`：保留预占（**不重复扣额度**）与已完成步骤，状态回 `queued`，
    由 worker 现成的 re-enqueue 路径重投（对 RQ 和本地 --once/--loop 都生效）；
    追加 warning 事件 + `moxie_task_retries_total` 指标。
  - 达到上限：落 `failed` 死信，释放预占，不再自动重试。
  - 取消 / TaskReschedule / 成功路径逻辑不变。
- 不在 enqueue 加 RQ `job_id`/`retry`：前者会与重投矛盾（同名 job 被 RQ 去重会阻止重试），
  后者会与 execute_task 层重试叠加——重试逻辑统一在一层更清晰。
- 单测 `test_task_retry.py` +2：验证 3 次尝试的 queued→queued→failed 轨迹、
  重试期间预占保留（额度不重复扣）、`max_attempts=1` 关闭重试。
- 已知限制：重试无退避（依赖任务执行本身的耗时形成间隔），上游持续 429 场景仍会快速耗尽次数。

### 3. API 出参契约（示范，非全量）

`schemas.py` 明确约定"响应统一用 dict，便于按字段演进"，全量强加 `response_model` 会裁剪动态字段、
破坏该约定。采取保守策略：只给结构永久稳定的接口加契约。

- `GET /v1/crypto/public-key` 加 `response_model=PublicKeyResponse`（algorithm/key_id/public_key 三字段固定）。
- schema 文件头注释更新，说明"多数响应仍用 dict，仅稳定接口声明契约"。
- 单测 `test_openapi_contract.py` +2：验证 OpenAPI 该接口 200 出参指向 `PublicKeyResponse` 组件、
  必填字段正确；验证 response_model 未裁剪运行时字段。

## 测试隔离修复

全量 pytest 时 `test_telemetry` 曾因 `caplog` 捕获不到日志而失败（单独跑通过）——

挂自定义 `_ListHandler` 直接捕获，完全绕开全局 caplog 状态，跨测试隔离验证通过。
