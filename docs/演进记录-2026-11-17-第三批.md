# 在线版持续演进 · 第三批（2026-11-17）

本批承接前两批的 P1/P0 清单，落地三块：**SSE 接线取代轮询**、**合规闸门外服务端留痕**、**上传内容安全嗅探**。所有改动仍在工作区未提交。

## 本批完成清单

### 1. 实时同步：SSE 接线取代 1.8s 固定轮询

**现状**：后端早有 SSE 端点 `GET /v1/agent-runs/{id}/events`（Bearer 头鉴权 + 可选 payload 帧加密，按 `seq > since` 去重，60s 自动关闭），前端 `streamRunEvents()` 也已实现——但全项目零调用，Workspace 仍用 `setInterval(1800ms)` 拉整份详情。

**改动**：
- 新增 `client/src/composables/useRunStream.ts`：封装「SSE 优先、失败自动降级轮询」的调度器。
  - 事件到达时按节流（默认 500ms）触发 `loadRun(true)`；SSE 只有日志事件（seq/stage/message），不含状态与正文，详情仍靠 `getRun` 拉取。
  - 用事件最大 `seq` 作下次连接的 `since`，配合服务端 `seq > since` 天然去重。
  - 流正常结束（后端 60s 上限 / 任务终态）后再强制刷新一次，兜底捕获「无日志事件的状态跃迁」。
  - 流抛错（端点 404/405/501、网络中断、鉴权失效）自动降级为 1800ms 轮询；`stop()` 会 abort 流并清 timer，用 generation 计数防切换任务竞态。
- `Workspace.vue` 移除 `pollTimer`/`startPolling`/`stopPolling`，改接 `live.start(id)` / `live.stop()`；挂载、切换任务、状态 watch、任务中心联动、卸载等调用点全部复用同一入口。
- 单测 5 个：降级、终态停止、paused 停止、since 去重、`stop()` 中断。

**坑**：SSE 端点只认 Bearer 头 → 不能用原生 `EventSource`（无法设自定义头），必须用现有 `fetch + getReader` 方案；也不能走 `apiFetch`（60s 默认超时会误杀长连接）。

### 2. 合规闸门：结构化权利声明 + 服务端留痕

**现状**：参考改编只查明文头 `X-Rights-Confirmed`——该头不在 payload 加密 AAD 内、可任意伪造，且 `agent_runs.py` 通过时不写任何授权留痕（`tasks.py` 仅把布尔写进 Task.params）。本质是「客户端自声明」，无服务端证据链。

**改动**：
- `schemas.py` 新增 `RightsDeclaration`（`basis`: own/authorized/public_domain，`rights_confirmed`/`ai_notice_ack` 必须为 true，`note` 可选）；`AgentRunCreateRequest` 加可选 `rights` 字段。`AgentRunCreateRequest` 走 `/v1/agent-runs`，不在 payload 加密豁免列表 → 声明随加密 body 提交，服务端可信。
- 新增 `services/compliance.py::enforce_rights_declaration()` 统一闸门：
  - 校验声明合法性（schema 层）；非法 → 422。
  - 每次通过写 `LegalConsent`（consent_type=`rights_adaptation`，version=`legal_terms_version`，含 IP/UA），按 `(account, type, version)` 唯一键幂等。
  - 写 `AuditLog`，meta 含 `basis`/`ai_notice_ack`/`source`/`source_key`/`terms_version`/`note`。
  - **明文头保留兼容**：无 body 声明但带头/旧布尔参数时放行，但 `source` 标为 `plaintext_header`、`basis` 标为 `header_legacy`，审计可见——旧客户端不破坏，新声明可强验证。
- `agent_runs.py` / `tasks.py` 两处闸门统一改调该服务；`agent_run.create` / `task.create` 审计 meta 补 `rights` 摘要。
- `tasks.py` 里 `params.rights_declaration` 是动态 dict，手动 `model_validate` 的 pydantic 错误原本会 500 → 捕获转成 422 `rights_declaration_invalid`。
- 单测 5 个：结构化声明通过+留痕、明文头兼容标注、无声明拒绝、非法字段拒绝、幂等（一条 Consent / 多条审计）。

**未做**：客户端 `createRun()` 目前对 reference 固定带头、无勾选 UI；完整 basis/note 的采集组件在桌面 Web 端（`web/src/components/ComplianceGate.vue`），尚未接入 client 在线版。本批先把服务端可信通道与留痕建好，前端采集可后续接。

### 3. 上传内容安全嗅探

**现状**：`services/uploads.py` 只做扩展名白名单 + 大小限制，无内容校验——`.txt` 里塞 EXE/图片/非 UTF-8 乱码都能存进去。

**改动**：
- `sniff_text_head(head)`：预读头部 4096 字节，三重校验——禁 NUL 字节、禁二进制魔数（PE/ELF/ZIP/PDF/PNG/JPEG/GIF/RIFF/GZIP/BZ2/RAR/7z/WASM 等）、须为合法 UTF-8（incremental decoder，允许边界处截断的多字节，避免误判）。
- `save_upload()` 改为「预读头部 → 嗅探 → `_PrefixedReader` 把头部拼回流首 → 写入」：嗅探在 `put_stream` **之前**完成，失败时零半成品；对 LocalStorage/DBStorage/S3 三种后端透明。超限/空文件的清理逻辑不变。
- 新错误码：`source_content_binary`（二进制伪装）、`source_content_encoding`（非 UTF-8），均 422。
- 单测 4 个（追加到 test_uploads.py）：魔数伪装、NUL 字节、GBK 非 UTF-8、合法中文多字节在边界不误判。

**约束**：当前上传白名单全是文本类型（`.txt/.md/.markdown/.csv/.json`），封面图片走独立的 `save_uploaded_cover`（Pillow 校验，不受影响）。若白名单将来扩展到二进制类型，嗅探需按扩展名分流。
