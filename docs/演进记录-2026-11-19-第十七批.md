## 11. 用户自助退款申请（用户反馈：申请退款没有入口）

- 排查结论：服务端已有 `GET /v1/refunds`（记录）、管理端 `POST /admin/orders/{id}/refund`（直接调渠道真退钱）与审核页，但**用户端没有自助申请 API，也没有任何 UI**。
- 设计：用户申请只创建 `status=pending` 的退款记录，**不调用支付渠道**；管理端在"订单与退款"页审核通过时才会真正退款，复用现有 `approve_refund` 闭环。金额按已用量折算（`refundsvc.quote`），用户可指定但不得超过可退上限。
- `server/app/api/payments.py` 新增 `GET /orders/{order_id}/refund-quote`（归属校验 + 折算报价）与 `POST /orders/{order_id}/refund-request`（归属/可退金额校验、防重复 pending、幂等、审计 `order.refund.request`）；`schemas.py` 新增 `UserRefundRequest`。
- `client/src/services/billingApi.ts` 新增 `fetchOrders()` / `fetchRefunds()` / `fetchRefundQuote()` / `requestRefund()` 与 `UserOrder` / `UserRefund` / `RefundQuote` 类型。
- `AccountSettings.vue` 新增"订单与退款"区块：可退款订单列表 → 查询折算金额 → 填原因提交 → 展示退款记录状态；刷新按钮。
- 新增 `server/tests/test_user_refund.py`（报价 / pending 申请 / 防重复 / 归属隔离 / 管理端审核闭环 / 审计）。
- 在线 E2E 主链加入退款 UI 段：申请退款 → 校验"退款记录/待审核"；账号注销时 pending 退款由 `purge_account` 外键级联清除。

## 12. BYOK 支持自选模型（用户反馈：没配置是哪个模型）

- 排查结论：BYOK 原本只让用户填 Key，服务端 `resolve_step_model` 只把 Key 替换进**平台默认模型**（DeepSeek），用户既看不到用的是哪个模型，也无法指定自己的模型/网关。
- 承载体：新增 `server/app/services/byok.py` 的 `ByokConfig`（`str` 子类，本体即 api_key，附带 `model`/`base_url`），Redis 存 JSON（TTL 1h，不落库不写日志），`from_stored` 兼容旧裸 key；`byok_from_headers` 从请求头组装。
- 集中覆盖：`resolve_step_model` 识别 `ByokConfig.model/base_url` 属性统一覆盖 model/base_url，`source="byok"`；engine/runners 现有 9 处 `api_key=...` 调用链零改动即生效（str 子类特性）。
- 接收层：`agent_runs.py` `_store_byok`、`tasks.py`、`gateway.py` 读 `X-BYOK-Model`/`X-BYOK-Base-URL`，base_url 复用 `validate_upstream_base_url` 做 SSRF 校验（受 `model_gateway_allow_private_networks` 控制）；worker `_fetch_byok` 解析 JSON。CORS 白名单加两个新 header。
- 网关优先级：BYOK model/base_url > 请求体 model > 后台工序配置 > 环境变量；BYOK key 优先于后台 Key。
- 客户端：`byok.ts` 存 `{key, model, baseUrl}`（兼容旧 `mx_byok_key`），`byokHeaders()` 增两个头；`Plans.vue` BYOK 区块增加模型名/接口地址输入与 OpenAI/DeepSeek/通义/自定义快捷选项。
- 测试：新增 `test_byok_model.py`（str 子类、头组装、模型覆盖、网关覆盖与 SSRF）、`byok.test.ts` 扩展；更新 `test_agent_runs.py` Redis JSON 断言。
