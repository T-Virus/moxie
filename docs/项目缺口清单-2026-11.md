### P2-1 Compose 未实测，且缺重启策略、备份与告警方案

- **证据**：`server/README.md:317` 自述 Compose 未验证；`server/docker-compose.yml` 无 `restart:`（仅 `minio-init` 为 `restart: "no"`）；全仓无 `pg_dump`/备份脚本；`/healthz`（`server/app/api/admin.py:22-28`）不检查 DB/存储，`/readyz`（`:31-45`）只查 DB+Redis，未查 S3/LLM。
- **影响**：部署失败率高；实例崩溃不自动拉起；数据库/对象存储无恢复手段；故障无外部告警。
- **建议动作**：实跑 Compose 并纳入发布前检查；`restart: unless-stopped`；备份 cron（DB + 对象存储）与恢复演练；接入外部 uptime/告警。
- **外部依赖**：Docker、备份存储、监控服务。

### P2-2 指标分散在进程内，worker 无指标端点

- **证据**：`server/app/metrics.py:14` 计数器为进程内字典；`server/docker-compose.yml:77` 启动 2 个 uvicorn worker；worker 进程未暴露 `/metrics`；`/metrics`（`server/app/main.py:151-163`）仅补一个 `moxie_queue_depth` 派生值。
- **影响**：模型调用成本、任务成功/失败、回调失败等关键指标不可观测（worker 侧计数永远抓不到）。
- **建议动作**：采用 `prometheus_client` 多进程模式或独立指标导出；worker 暴露指标端口；补充成本/失败率面板。
- **外部依赖**：监控系统（Prometheus/Grafana）。

### P2-3 无 PostgreSQL 集成测试、无压测、并发路径未被覆盖

- **证据**：`server/tests/conftest.py:18` 全部 SQLite + `TestClient`；`server/app/scheduler.py:64` 使用 `with_for_update(skip_locked=True)`，SQLite 不支持该语义，测试无法覆盖；`e2e/` 仅桌面本地模式 smoke（`e2e/tests/desktop.spec.ts`），无云链路与管理后台 E2E；无压测脚本。
- **影响**：租约回收、额度预占并发、真实网络/DB 行为未知，线上可能重复执行或超卖。
- **建议动作**：CI 增加 Postgres service 跑关键用例；补额度并发与租约回收测试；k6/locust 基线；云链路 Playwright 用例。
- **外部依赖**：CI 资源（含 Postgres 服务容器）。

### P2-4 文档与配置多处不一致（既有说明，亦有新增矛盾）

- **证据**
  - live 测试：`server/README.md:337,354` vs `server/tests/test_payments.py:441,448,455` 无条件 skip。
  - 发票路径：`server/docs/payments.md:172` vs `server/app/api/payments.py:312`。
  - 管理接口：`server/README.md:416` 写 `GET/POST /v1/admin/invoices`，实际用户侧为 `POST /v1/invoices`（`payments.py:108`），管理侧为 `GET /v1/admin/invoices`。
  - 安全默认值：`.env.example:32` 同时给出 `ENV=production` 与 `PAYMENTS_FAKE_ENABLED=true`，与「生产务必 false」注释矛盾（见 P0-1）。
- **影响**：运维按文档操作会失败，最危险的是把 fake 支付开关带进生产。
- **建议动作**：拆分 `.env.production.example`（安全默认值）；接口文档改由 OpenAPI 生成；README 增加「生产检查清单」。
- **外部依赖**：无。

### P2-5 测试/开发残留物未清理

- **证据**：`server/novel_server.db`（221KB，空表）与 `.pytest_cache` 存在；`dist/data/_system/tasks.json(.tmp)`、`dist/config/*`；根目录 `pyarmor.bug.log`；工作区 `.tmp_third/`（含 `test_all.py`、`Moxie-1.1.0.zip`、`chapters.json` 等临时数据），且为未跟踪目录。
- **影响**：误提交/误分发；审计时容易把临时产物当作正式功能。
- **建议动作**：清理并补充 `.gitignore`（`.pytest_cache/`、`.tmp_third/`）；正式产物与临时验证目录分仓/分目录。
- **外部依赖**：无。

### P2-6 CI 与 E2E 已建立，但覆盖面不足且未覆盖迁移漂移

- **证据**：`.github/workflows/ci.yml` 覆盖 server pytest（`-m "not live"`）、桌面 unittest、web build、Playwright 桌面 smoke；`package.yml` 手动打包。CI **未**执行 `alembic upgrade head`/`alembic check`、未测 Compose、未测管理后台、未测云任务链路。
- **影响**：像 P0-3 这类「迁移缺表导致启动失败」的致命问题不会被 CI 拦截。
- **建议动作**：CI 增加「临时 Postgres 迁移 + `alembic check` + 启动冒烟」；补后台与云端 E2E。
- **外部依赖**：CI 资源。

### P2-7 生产环境默认暴露 `/docs`、`/openapi.json`、`/`

- **证据**：`server/app/main.py:102-103` 设置 `redoc_url="/redoc"`、`openapi_url="/openapi.json"`；`:165-173` 根路径返回文档入口；无按 `ENV` 关闭逻辑。
- **影响**：完整接口面与错误码对外可见，配合 P0-1 更易被快速利用。
- **建议动作**：生产关闭 docs/openapi 或加鉴权；保留内部可用开关。
- **外部依赖**：无。

### P2-8 自动更新已接线，但签名密钥/发布与回滚演练证据缺失

- **证据（当前工作区）**：`src/updater.py` 已实现 SHA256 + Ed25519 校验与 pending/rollback（`:6,20-30` 等），`src/webapp.py:53,3090-3096` 已接线 `check_update/download_package/apply_pending/rollback`；但 `.tmp_third/update.json`、`version.json` 为临时验证数据，未见正式签名密钥配置与发布流水线闭环（`package.yml` 仅打 frontend/exe 制品）。
- **影响**：更新链路缺少可运营的密钥管理与灰度/回滚演练，出错后只能人工干预。
- **建议动作**：明确更新签名密钥托管（离线私钥）、发布流水线自动签名、灰度渠道与强制回滚开关；接入崩溃率观测。
- **外部依赖**：更新服务器/对象存储、签名密钥托管。

### P2-9 移动端未接入云端（当前无任何云端能力）

- **证据**：`mobile/` 全目录搜索 `cloud|云端|License|license` 无有效实现命中（仅注释/占位）；桌面端 `web/dist` 可复用到 Android assets，但云模块未移植。
- **影响**：移动端用户仍是纯本地模式，与云端订阅的商业模型脱节。
- **建议动作**：按二期计划移植登录/设备/License/任务/产物下载；确认 Chaquopy 打包不含明文提示词（既有约束）。
- **外部依赖**：Android 打包链路与签名密钥。

### P2-10 运营闭环缺提示与导出（对账差异、额度调整、审计检索）

- **证据**：对账差异可查询/导出 CSV（`server/app/api/payments.py:260`），但无告警通知与差异处理工作流；`admin/src/api.ts:306-309` 的额度调整接口不存在（见 P1-1）；审计日志仅 `GET /admin/audit-logs`（`server/app/api/admin.py:48`），无导出/检索界面。
- **影响**：对账差异、异常用量、额度争议依赖人工查库，处理时效与可追溯性差。
- **建议动作**：对账差异接入通知与工单标记；补额度调整接口与审批留痕；审计日志导出。
- **外部依赖**：无（通知依赖 P1-4）。
